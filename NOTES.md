# Teaching notes

- Use the real Codex Usage Monitor as the teaching project.
- Prefer one small, reversible UI experiment at a time.
- Explain the boundary between appearance, state, and behavior before asking for an edit.
- The user currently prefers compilation and manual UI inspection without added automated test cases.
- User-visible product changes should also update the README, operating notes, and relevant implementation plan.
- Teach comparative repository reading: extract contracts, failure modes, and verification evidence instead of copying visible features.
- Preserve a distinctive native, Codex-first, trust-focused product promise when evaluating broader dashboards.
- Use a short feature evidence card before implementation: user job, source of truth, ownership, privacy boundary, failure behavior, verification, and provenance.
