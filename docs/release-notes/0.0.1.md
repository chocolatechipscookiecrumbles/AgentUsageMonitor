# Agent Monitor 0.0.1

Menu-bar usage monitor for **OpenAI Codex** and **Claude Code**: five-hour and
weekly limits, reset countdowns, threshold alerts, and a per-agent token monitor
read from records already on your Mac. Non-commercial.

First public build. The app was previously called *Codex Usage Monitor*; it covers
Claude Code as well now, so the product is **Agent Monitor**. The bundle and the
download are still named `CodexUsageMonitor` — that rename comes later, so it does
not disturb this release.

## Install

1. Download and unzip `CodexUsageMonitor-0.0.1.zip`.
2. Move `CodexUsageMonitor.app` to `/Applications`.
3. Launch it — it lives in the **menu bar**. There is no Dock icon and no window
   on first launch; look at the right end of the menu bar.

**Published artifact:** Agent Monitor 0.0.1 build 266 is Developer ID signed,
notarized, and stapled. The uploaded archive was downloaded and verified after
publication on 2026-07-31; Gatekeeper accepted it and the app worked as intended.

## Requirements

- macOS 14 (Sonoma) or later.
- The Codex CLI and/or Claude Code, already signed in. This app adds no account
  of its own.
- No Python or other runtime — the Claude usage bridge is currently a second native
  executable bundled inside the app.

## How Claude usage is read — please read before installing

This app reads Claude usage using the OAuth credential **Claude Code already
stored in your Keychain**. macOS asks your permission the first time; background
refreshes never prompt again. Nothing is uploaded. The quota path reads only usage
percentages and reset times; the separate Token Monitor selectively decodes usage
metadata from local records and does not retain, export, or transmit record content.

**Anthropic's Terms of Service do not permit a third-party application to reuse
that credential.** This build does it anyway. That is stated here, in the
README, and in the app's own **Data & Privacy** page rather than buried, so
installing is an informed choice. Using it may put your Anthropic account at
risk of enforcement; that risk is yours to weigh. Turning Claude off in
**Settings → Agents** stops the read entirely.

Replacing this with a **first-party OAuth client** — the app requesting its own
authorization instead of borrowing Claude Code's — is the first work planned
after this release.

Codex usage is read from your local Codex CLI's app-server and carries no such
caveat.

## What it does

- **Menu-bar readout** of the most-consumed window, or a two-line text label,
  bars, or a single-provider style — your choice in **General**.
- **Per-agent popover** with five-hour and weekly windows, reset timing, and a
  status pill. The header names your plan.
- **Token Monitor** — tokens observed from Codex's and Claude Code's own local
  records on this Mac, by **day** or by **week**, with a chart, per-category
  totals, model shares, and the last request. Independent of quota, so it keeps
  working while a provider is disconnected. Nothing is uploaded and no tokens
  are spent to produce it.
- **Threshold alerts** per provider, plus optional forecast, reset, stale-data,
  and refresh-failure warnings.
- **App-local disconnect** — hide a provider without signing out of its CLI or
  touching its stored credential.
- **Data & Privacy** page listing every file the app writes, with reveal, copy
  path, and export.

## Known limitations

- **The popover can outgrow a small screen.** With the Token Monitor at its
  tallest, the Codex tab is about 915 points against roughly 775 usable at
  1280×800. It does not scroll by design. Turn off sections you do not need in
  **Settings → Agents → Token Monitor**.
- **GitHub Copilot is not supported.** No personal-quota API has been verified
  for it; it is absent rather than broken.
- **Claude's weekly window is shared** with Claude chat, not Claude Code alone.
- **Editing keyboard shortcuts is not possible yet.** The four popover commands
  have fixed key equivalents, listed in **General**.
- **The Claude status-line bridge is a second executable.** It is signed and
  notarized correctly in 0.0.1, but it makes the bundle contain two executable
  binaries and requires inside-out signing. A future consolidation will move the
  bridge entry point into a non-UI mode of the main app executable so the bundle
  contains one executable binary without changing the status-line privacy or
  reliability contract.
