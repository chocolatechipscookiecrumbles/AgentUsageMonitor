Find, edit, and preview the UI

Your first win: make one reversible Settings-window layout change, rebuild the real app, and explain why the same edit would be risky in the native menu.

1. Use the three-layer mental model

LayerQuestionThis project
SceneWhere does the UI appear?MenuBarExtra and Settings in CodexUsageMonitorApp.swift
ViewWhat does it look like?QuotaMenuView and SettingsView
State/actionWhat data drives it, and what happens on interaction?QuotaViewModel, AppSettings, bindings, and button actions

For a visual-only change, begin in the View layer. Do not start in the model because a label, spacing, or color change should not alter persistence or notification logic.

2. Recognize declarative SwiftUI

Section("Warnings") {
    Toggle("Remaining quota warnings",
           isOn: $settings.thresholdWarningsEnabled)
    Text("Uses fixed thresholds…")
        .font(.caption)
        .foregroundStyle(.secondary)
}

This describes a section containing a control and supporting text. The dollar sign passes a two-way binding: changing the toggle changes the setting, and changing the setting updates the toggle. The chained modifiers affect appearance.

3. Know the menu boundary

The current menu uses native menu presentation. Its root Group supplies rows such as Text, Toggle, Button, and Divider. In this context, a Button becomes an inline menu command.

A root VStack plus .menuBarExtraStyle(.window) is not merely spacing. It intentionally changes the presentation into a custom panel, which is why the commands previously looked like large buttons.

4. Make your first reversible edit

  1. Open Settings/SettingsView.swift.
  2. Find .frame(width: 540, height: 520).
  3. Change only the width from 540 to 600.
  4. Build and relaunch using the commands below.
  5. Open Settings…, compare the result, then choose whether to keep or restore 540.
cd "/Desktop/agent usage/CodexUsageMonitor"
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash Scripts/build-app.sh
pkill -x CodexUsageMonitor
