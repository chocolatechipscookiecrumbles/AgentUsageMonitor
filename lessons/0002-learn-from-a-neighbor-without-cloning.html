Learn from a neighbor without cloning

Your win: turn one attractive feature from another repository into a small, distinctive, evidence-backed feature proposal for this app.

1. Name the user job first

“Token Monitor has session details” is an observation, not a requirement. A requirement begins with what your user should be able to decide or do.

Weak: Add session watching like Token Monitor.

Stronger: Let a Codex user see whether recent work is consuming quota unusually quickly without opening a full analytics dashboard.

2. Separate the source from the product

QuestionExample answer
What is the source?Local Codex JSONL session records
What is the parser output?A sanitized LocalUsageSnapshot
What is the product feature?A small session pulse tied to recent quota pace
What is deliberately omitted?Prompt text, public sync, leaderboard, and broad provider coverage

This keeps implementation details replaceable. Tokscale might be the first comparison oracle and a native Swift parser the eventual production owner; the visible feature does not need to know.

3. Classify what you are borrowing

  1. Idea: session usage can update after a local transcript changes.
  2. Contract: source-specific parsing produces normalized tokens, model, session, and time fields.
  3. Implementation: specific discovery, parsing, cache, or watcher code.
  4. Identity: name, icons, screenshots, layout, and brand.

Ideas and contracts are the best learning material. Implementation requires provenance and license care. Identity is where accidental cloning usually happens.

Retrieval check

Why should local token usage not be added to QuotaPresentation?

Quota state and local log analytics have different sources, freshness rules, failure modes, privacy boundaries, and consumers. Combining them would make both harder to reason about and test.

What should a file watcher own?

Only an invalidation signal: something may have changed. Discovery, parsing, aggregation, scheduling, and UI state belong elsewhere.

When is another project a comparison oracle?

When you run both implementations on the same sanitized input and use their agreement or disagreement as evidence without making the other project a production dependency.
